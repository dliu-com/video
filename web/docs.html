How it works

video.dliu.com hosts videos that anyone can watch and that other dliu.com sites can embed. There are no servers: files sit in S3, CloudFront delivers them, and one small Lambda function runs only when the owner signs in or changes a video.

Running costs

Everything is billed per use. With nobody watching, the only charge is storing the videos in S3.

Security

Anyone can watch; only the owner, signed in with Microsoft, can upload, edit or delete.

How this site is tested

Every 15 minutes, status.dliu.com visits this site from three places around the world, like an ordinary visitor who isn't signed in. It opens the public pages, makes sure the locked doors are still locked, and asks the site to check its own video list and sign-in settings. It never signs in and never changes anything.

What isn't tested

These all need the owner to sign in, and the checker never does, so they are covered by the code tests and by the owner.

  • Signing in at Microsoft and getting a session
  • Uploading, replacing, editing and deleting videos and posters
  • Converting uploads into streaming versions
  • Using the tools API with a real Microsoft pass
  • Playing a particular video, because which videos exist changes

The API for tools and AI agents

Watching needs no API. The API lets tools, scripts and AI agents that the owner trusts manage videos on the owner's behalf: list, upload, replace, edit and delete. They first sign in with Microsoft and get a pass that only allows particular things.

Good to know

  • Finishing an upload publishes it; replacing a file changes what every link and embed plays.
  • Deleting is permanent; there is no recycle bin.
  • Upload links are like keys: never paste them into chats, logs or code.
  • Do one thing at a time to a video, and send only the changes you mean.
  • How to get a pass is described once, in the Auth API documentation.
